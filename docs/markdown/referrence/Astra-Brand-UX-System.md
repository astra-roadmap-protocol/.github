## SECTION 4: MOTION & INTERACTION DESIGN

### 4.1 Animation Principles

**Astra Motion Language:** Smooth, purposeful, never distracting

```css
/* Timing */
--duration-fast:    150ms     /* Micro-interactions */
--duration-normal:  300ms     /* Standard transitions */
--duration-slow:    500ms     /* Entrance animations */

/* Easing Functions */
--ease-out:         cubic-bezier(0.0, 0.0, 0.2, 1)      /* Objects leaving */
--ease-in:          cubic-bezier(0.4, 0.0, 1.0, 1.0)    /* Objects entering */
--ease-in-out:      cubic-bezier(0.4, 0.0, 0.2, 1)      /* Standard */
```

### 4.2 Interaction Patterns

**Hover States:**
- Color shift (primary → light variant)
- Slight elevation (shadow increase)
- No scale transformation (feels unnatural)

**Focus States:**
- Visible outline (for accessibility)
- Teal colored (#208A91) with 3px width
- 2px offset from element

**Loading States:**
- Spinner (rotating Astra star icon)
- Subtle pulsing progress bar
- Contextual loading text ("Generating your roadmap...")

**Feedback States:**
- Success: Green checkmark + toast notification
- Error: Red alert icon + detailed error message
- Warning: Orange alert icon + guidance

## SECTION 5: ACCESSIBILITY STANDARDS

### 5.1 WCAG 2.1 AA Compliance

**Color Contrast:**
- Normal text: 4.5:1 minimum (teal on white = 5.2:1 ✓)
- Large text: 3:1 minimum
- Icons/decorative: 1:1 acceptable

**Typography:**
- Minimum 14px body text (scalable)
- Line height minimum 1.4 for body
- Max line length 70 characters for readability

**Keyboard Navigation:**
- All interactive elements accessible via Tab
- Focus order logical (left-to-right, top-to-bottom)
- Skip to main content link visible on focus

**Screen Readers:**
- Semantic HTML (button, nav, article, etc.)
- Alt text on all images (descriptive, not redundant)
- ARIA labels for complex components
- Form labels properly associated

## SECTION 10: USABILITY TESTING & ITERATION

### 10.1 Testing Plan

#### **Phase 1: Early Concept Testing (Week 1-2)**

**Participants:** 5-8 developers + 2-3 non-technical users

**Methods:**
- Unmoderated tasks (5-minute video recording)
- Think-aloud protocol (observe while they explore)
- Post-task survey (System Usability Scale)

**Key Questions:**
1. "What's the first thing you'd do on this screen?"
2. "Can you find your completed roadmaps?"
3. "How would you upload a GitHub repo?"
4. "Would you create/buy marketplace content?"

**Success Criteria:**
- Task completion ≥75%
- SUS score ≥70
- Zero major confusion points

#### **Phase 2: MVP Testing (Week 4-5)**

**Participants:** 15-20 users (diverse roles)

**Methods:**
- Moderated user testing (60 min each)
- Task sequences (realistic workflows)
- Problem discovery interviews

**Tasks:**
1. Sign up and authorize GitHub
2. View and explore generated roadmap
3. Ask AI tutor a question
4. Find marketplace and buy workflow

**Success Criteria:**
- 80% complete sign-up
- 90% understand roadmap visualization
- 70% find marketplace content
- NPS ≥40

#### **Phase 3: Beta Testing (Week 8+)**

**Participants:** 50-100 opt-in beta users

**Methods:**
- In-app feedback (feature requests)
- Weekly surveys (NPS, feature priority)
- Analytics tracking (usage patterns)
- Bug reporting system

**Feedback Channels:**
- Slack community
- Discord #feedback channel
- In-app feedback widget
- Monthly user interviews (5-10 users)

### 10.2 Iteration Framework

**Weekly Cycles:**

```
Monday:    Review feedback + bug reports
Tuesday:   Design solutions for top 3 issues
Wed-Thu:   Develop + test fixes
Friday:    Deploy + monitor
```

**Monthly Priorities:**

1. **Fix:** Critical bugs (blocks 10%+ of users)
2. **Improve:** Friction points (test results show confusion)
3. **Expand:** New features (top user requests + roadmap)

### 10.3 Metrics to Track

**Engagement Metrics:**
- DAU (daily active users)
- Session duration
- Feature usage (which screens visited most)
- Roadmap completion rate

**Conversion Metrics:**
- Sign-up → Roadmap generated
- Free → Paid conversion (10% target)
- Creator earnings (average $50-200/month)

**Quality Metrics:**
- Error rate (< 0.5%)

**Retention Metrics:**

## SECTION 15: BRAND VOICE & MESSAGING

### 15.1 Tone & Voice Guidelines

**Tone:** Helpful, confident, approachable, never condescending

**Voice Characteristics:**
- Clear over clever
- Action-oriented
- Empathetic to frustrations
- Expert but accessible

**Examples:**

✅ **Good:**
"Understand any codebase in hours, not weeks."
"Your code explained. By code."
"For developers who care about understanding."

❌ **Bad:**
"Disruptive AI-powered learning paradigm shift"
"Literally the best roadmap generator ever"
"Complex code made easy!" (oversimplifies)
